최종 발표에서 알고리즘 설명을 맞출 항목

현재 배포 모듈: DMD CPU64 INT8.
기존 V1 중간 발표의 8x8x6 주변 배치 벡터와 방향장 추가 검증 설명은 이 모듈의 설명이 아니다.
과제 14쪽은 발표·시연과 제출물 불일치를 감점 사유로 명시하므로, 최종 발표에서는 아래 흐름으로 맞춘다.

1. 밝기·대비 보정 후 FingerJet으로 특징점을 추출한다.
2. 품질순 최대 64개를 선택한다. DB마다 다른 개수나 기준을 쓰지 않는다.
3. 원본 영상에서 각 특징점 위치·방향에 맞춘 128x128 패치를 만든다.
   밝기 보정 영상은 FingerJet용이며, DMD 패치는 검증한 원본 영상에서 생성한다.
4. DMD 사전학습 모델을 ONNX Runtime CPU에서 실행한다.
   특징점별 768차원 표현과 64개 마스크 값을 만든다.
   모델을 재학습한 것이 아니라 외부 예시 영상으로 INT8 양자화 범위를 보정했다.
5. 마스크를 반영한 특징 유사도를 계산하고 Hungarian 방법으로 중복 없는 대응을 선택한다.
6. LSAR 방식으로 대응 사이 거리·방향 관계를 검증한다.
7. 최종 점수를 0~1 범위, 소수점 셋째 자리로 반환한다.

C++ 코드 위치
algorithm-dmd/src/photometric.h: 대비 보정
algorithm-dmd/src/algorithm.cpp의 extract, patches, Runtime::infer: 특징점·패치·CPU 추론
algorithm-dmd/src/matcher.h의 similarity, assign, compare: 유사도·대응·관계 검증
algorithm-dmd/src/algorithm.cpp의 encode/decode/boundary: 템플릿·오류 처리
KISA_Enroll, KISA_Attempt, KISA_Compare: 평가 프로그램 인터페이스

제시할 결과
CPU 5초 연속 인식과 EER은 docs/최종_검증결과.txt 및 evidence의 최신 기록을 사용한다.
INT8 평균 가우시안 EER은 0.446429%, 개별 DB2는 1.339286%로 정확도 손실을 함께 설명한다.
PDF에 250ms 제한이나 EER 1% 합격선이 있다고 발표하지 않는다.
5초는 별도로 확인 중인 운영 목표이며 시험 PC·Worker 수와 측정 범위를 밝힌다.

이 문서는 알고리즘 발표 연결 자료다. GUI 평가 프로그램, 팀원 역할·기여도,
각 평가 항목 시연, 전체 PPT는 팀의 최종 발표 자료에서 함께 완성해야 한다.
