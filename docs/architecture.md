# 설계 및 요구사항 현황

## 구조

GUI → fp_bench → 독립 fp_task 프로세스 → KISA DLL.

GUI는 별도 스레드에서 배치 엔진을 실행하므로 메시지 루프를 막지 않는다. CLI 엔진은 등록, 비교용 추출, 비교 단계를 분리한다. 각 단계는 선택한 수의 스레드로 프로세스를 배치한다.

각 Worker는 Job Object에 할당되며, 시간 초과·취소 시 하위 프로세스까지 종료한다. DLL 호출 전 현재 단계를 디스크에 기록하여 비정상 종료 이후에도 어느 단계였는지 파악한다. 오류 코드와 오류 메시지 원본 바이트를 hex로 기록한다.

DLL 입출력 버퍼에는 접근 금지 경계 페이지를 두며, 입력은 읽기 전용으로 전달한다. 이는 흔한 잘못된 메모리 접근을 검출하는 장치이며 악의적 DLL에 대한 보안 샌드박스는 아니다. 선행 여유 바이트 안의 작은 underrun이나 할당 범위 안의 논리적 오류까지 모두 검출하지는 못한다.

## 목록·재현성

UTF-8 TSV 헤더: FPPLAN / 버전 / 시드 / 등록 정책.
행: pair_id / iType / DB 식별자 / G 또는 I / 등록 이미지 절대경로 / 비교 이미지 절대경로 / 행 버전.

파일명은 지문ID_촬영순번 형식으로 읽는다. 이미지에 서로 모순되는 DB/type을 부여하면 거부한다. 동일 파일과 중복 쌍을 거부한다. 현재는 배치 시작 전 디코딩된 동일 픽셀 데이터도 검사하여 재인코딩·이름 변경으로 같은 이미지를 비교하는 경우를 거부한다.

실행 폴더는 덮어쓰지 않으며 원본 기록은 작업 완료마다 flush한다. 입력 해시로 어떤 파일을 사용했는지 추적한다. 한 PC의 절대 경로를 저장하는 형식이므로 팀원 PC로 옮길 때 경로를 수정해야 한다. 상대 경로 기반 이동형 목록은 다음 개선 항목이다.

동일 DLL·같은 파일·같은 목록·같은 시드에서 1개/4개 병렬 실행의 점수 일치를 검증했다. 병렬 실행의 벽시계상 완료 순서 자체는 재현 대상이 아니다.

## 통계

인식 판정은 score >= threshold. FMR은 사전 정의 타인 비교 전체가 분모이며 성공 점수 중 판정 통과가 분자이다. FNMR은 사전 정의 본인 비교 전체가 분모이며 등록 실패·매칭 실패·임계값 미만을 분자에 포함한다.

EER은 프로젝트 PDF 8쪽의 이산 점수 추정 방식: 교점 양쪽 경계에서 FMR+FNMR 합이 작은 쪽의 두 값으로 구간을 정하고 중간값을 낸다. 선형 보간으로 대체하지 않는다. 교점이 정의되지 않는 실패 구성 또는 본인/타인 표본이 없는 경우 null이다. EER*는 성공 점수만의 별도 곡선에서 계산한다.

## 우선순위

평가 프로그램의 점수를 확보하려면 GUI의 실제 실행/취소 시연, 누락된 시험 선택과 리포트 옵션, Word/설치 패키지까지 마무리해야 한다. 알고리즘은 현재 성능이 부족하므로 실패 쌍 시각화와 독립 검증 분리 후 특징 추출·정합을 개선한다.
