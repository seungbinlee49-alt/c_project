# K-NBTC를 기준으로 한 고도화

확인일: 2026-11-03. 실제 제출·신청·담당자 연락은 하지 않는다. 사용자 요청은 외부 인증을 목표 수준으로 삼아 구현 품질을 높이는 것이다.

## 교수님이 말씀하신 곳

가장 유력한 곳은 KISA의 생체인식정보시험센터 K-NBTC이다. 프로젝트 설명서의 링크, 제공된 안내서 및 KISA_Enroll/Attempt/Compare 규격이 모두 이 제도를 가리킨다. 교수님의 발언 자체를 확인한 것은 아니므로 추론이다.

- 공식 소개: https://www.ksecurity.or.kr/kisis/subIndex/99.do
- 공식 신청 안내: https://www.ksecurity.or.kr/kisis/subIndex/102.do
- 2025년 11월 개정 안내서 게시물: https://www.ksecurity.or.kr/user/bbs/kisis/31/110/bbsDataView/33974.do

공식 자료실에서 확인한 개정본은 과제에 포함된 2025년 11월 안내서와 같은 제목이다. 안내서 15~16쪽은 지문인식에서 센서별 4개 DB 중 3개 DB가 EER 1% 이하일 것을 요구하며, FTE 또는 FTA가 5% 이상이면 시험 결과가 유효하지 않다고 설명한다. 이 값은 해당 안내서 기준이다. 우리 FVC DB 결과를 그 기관의 비공개 센서 DB 결과로 대체할 수 없다.

안내서는 신청 서류·사전시험·본 시험·인증 과정을 설명한다. 공식 신청 페이지는 사업자등록증과 신청서·보안서약서를 요구한다. 학생 팀의 신청 가능 여부는 확인하지 않았으며, 현재 실제 신청을 추진하지 않는다.

## 혼동할 수 있는 다른 곳

FVC-onGoing은 볼로냐대학교 BioLab의 비공개 데이터 온라인 평가 서비스이다. 합격 인증과는 다른 성격이다.

- https://biolab.csr.unibo.it/FVCOnGoing/UI/Form/Home.aspx
- https://biolab.csr.unibo.it/FVCOnGoing/UI/Form/BenchmarkAreas/BenchmarkAreaFV.aspx

공개 FV 규약은 Win32 콘솔 enroll.exe / match.exe, 입력 경로 인자 3개, 텍스트 로그 append, 0~1 유사도, 등록 5초/비교 3초 제한을 설명한다. 이전 호출을 이용한 학습·템플릿 갱신은 허용하지 않는다. 참고용 어댑터를 만들고 로컬 프로토콜 검사를 수행한다. 외부 서비스에 올리거나 호환성 승인을 받은 것은 아니다.

## 현재 구현

- 특징점 추출: FingerJetFX OSE의 공개 C++ 라이브러리 FRFXLL을 별도 DLL로 빌드.
- 직접 구현: 상대 좌표·상대 방향의 국소 descriptor, 대응 후보 생성, 기하학적 합의, 일대일 대응, 강체 정합 보정, 점수 계산.
- 최대 128개 특징점, 500 dpi 물리 단위 기준 동일 상수 적용. DB별 점수 조정 없음.
- 템플릿은 버전 및 손상 검사용 체크섬 포함. 체크섬은 인증/암호화 기능이 아니다.
- 과제 센서 타입 1/2/3과 안내서 타입 5/7/8/9의 크기 지원. 지문 픽셀은 헤더 없는 8비트 회색조.
- KISA 경로는 현재 500 dpi를 가정한다. 실제 센서 해상도와 최신 시험 환경은 외부 사양 확인이 필요한 항목으로 남긴다. 추가 FP_ExtractImage API는 해상도를 인자로 받는다.
- Worker는 DLL과 같은 폴더의 종속 DLL을 찾도록 로딩하며, 입력 읽기 전용 및 경계 페이지, 프로세스 격리와 취소를 유지한다.
- TIFF/BMP/PNG와 프로파일 크기에 맞는 헤더 없는 RAW 입력을 지원한다.
- 배치 엔진은 디코딩된 동일 픽셀의 비교도 거부한다. 읽을 수 없는 이미지는 Worker 단계에서 실패로 집계한다.

오픈소스는 특징점 추출이라는 단위 기능에 적용한다. 독립 실행 인식 소프트웨어를 호출하지 않는다. 출처와 원본 라이선스는 NOTICE.md 및 third_party에 보관한다. upstream의 역사적 MINEX 설명은 우리 전체 알고리즘의 인증을 의미하지 않는다.

## 현재와 목표의 차이

특징점 기반 첫 개발 시험의 EER은 원본에서 약 1.62%, 12.82%, 5.70%이다. 일반화 검증 결과도 인증 결과도 아니다. 현재 accept 수준을 달성했다고 판단하지 않는다.

인증 수준을 논하려면 최소한 미관측 독립 데이터, 센서별 정식 시험 조건, 실패율과 시간·메모리·인터페이스 검증이 필요하다. 현재는 독립적인 추가 DB와 K-NBTC 비공개 DB 결과가 없다.

## 다음 성능 개선의 규칙

현재 공개 B 세트는 이미 결과를 모두 확인한 개발용이다. 나중에 일부 ID를 떼어도 이를 처음 보는 최종 검증셋이라고 부르지 않는다.

1. 새로 확보한 데이터의 사용 조건과 촬영·사람/손가락 식별자를 확인한다.
2. 개발/보정/최종 검증을 사람 또는 손가락 단위로 구분하고 목록을 고정한다.
3. 개발 데이터에서만 알고리즘·전처리·임계값을 선택한다.
4. DLL·추출 라이브러리·상수·소스 해시를 고정한 뒤 검증한다.
5. 검증 결과를 보고 수정했다면 해당 검증셋의 노출 이력을 기록한다.
6. 실제 제출은 하지 않는다.
